# v0.5.0

## Summary

Restore a session from its ID alone. `/resume-from <id>` inside an agent, or `resume-from <id>`
in a shell, finds the session in any agent and profile, works out the directory, branch and
commit it ran in, recreates a removed worktree after confirmation, and resumes it — natively when
the agent is the same, by import when it differs. A short summary shows what was restored.

## Changes

- **One input: the session ID.** An exact ID, any case, or a prefix of 6 or more characters.
  Lookup is global, not limited to the current repository, and reads only the matching file. A
  prefix that matches several sessions lists them with their files; nothing is guessed.
- **Every profile is searched by default:** `~/.claude*/projects`, `~/.codex*/sessions`,
  `~/.codex*/archived_sessions` (files modified in the last 14 days), and
  `~/.pi/agent/*sessions*`, plus the agent home variables and configured `extraHomes`.
- **Same agent resumes natively.** The tool prints one command (`cd`, the profile variable when
  the home is not the default, and the agent's own resume command) and writes nothing.
- **A different agent imports into the session's own directory**, not the directory the command
  ran in. `--to <dir>` picks another checkout of the same repository; another repository is
  refused.
- **Removed worktrees are recovered after confirmation.** The preview shows the exact
  `git worktree add` command (recorded branch, `origin/<branch>`, recorded commit, or the
  repository's HEAD as a last resort); it runs only with the printed confirmation token and never
  fetches, forces or deletes.
- **`resume-from <id>` works in a plain shell** without `--target-agent`; it prints the native
  command and never imports.
- **`--prompt <text>`** adds the first prompt to the resume command. **`--context`** prints the
  conversation an import would keep, without writing anything.
- **A three-line restore summary** names the source, the directory and branch, and what crossed
  over. Claude Code shows it as a gray transcript line, Pi as a dim entry, Codex in the command
  output; it never enters the model context.
- **The skill restores instead of previewing.** `/resume-from <id> [instructions]` confirms the
  restore, opens the resumed session in a new agterm session or tmux window with the instructions
  as its first prompt, and can create a new worktree or use a named directory first.
- **Fixes:** the Claude Code import marker was invisible on resume and reached the model; it is
  now a gray, out-of-context entry. Imported Claude Code and Pi sessions no longer show a "model
  could not be restored" notice. Landings print the real native resume command instead of a
  placeholder. A session whose last line is still being written can be resumed natively.
- **Simplified:** one shared redaction module instead of three copies, one per-file reader per
  adapter, one confirmation flow in the Pi extension, and fewer duplicated contract restatements.

## Upgrade

Update the plugin or extension in each agent and restart it. The numbered list, rows, `--agent`,
`--home` and `--confirm` keep working; an ID or file path given to `/resume-from` is no longer
limited to the current repository.
